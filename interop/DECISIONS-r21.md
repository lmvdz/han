# Wire decisions for round 21

Fixed once, so the spec, the Python implementation and the TypeScript clean-room converge without guessing. Inputs: [RESULTS.md](RESULTS.md) (ranked root causes), [../cleanroom-ts/SPEC-GAPS-WIRE.md](../cleanroom-ts/SPEC-GAPS-WIRE.md) (W-01…W-47), and new W-48…W-51 found by the harness. Where an item below is silent, the spec agent decides and writes it down; the implementation agents follow the spec text as it lands.

| # | Topic (gap) | Decision |
|---|---|---|
| D1 | Spaces a server doesn't host (W-13, W-19) | A server with no record of the space answers `moved` with `movedTo` = the server named in the space id, for every call naming the space (`append` incl. `space.create`, `read`, `subscribe`, `blobGet`, `watch`), unless it *is* that server, in which case `not_found`. A server that moved a space away answers `moved` with the new home. `host` (G-06) is implemented by both. |
| D2 | Request frames (W-04, W-21a) | A request frame is exactly `{id, call, args}`: `id` a positive integer, `call` a known name, `args` an object (required, may be `{}`) with only the documented members. Anything else: an error reply `{id, error: {code: "invalid", message}}` (id 0 if the id itself is unusable). A frame that isn't I-JSON: error with id 0, `invalid`, and the server closes the connection. |
| D3 | Uploader's own unreferenced blobs (W-29) | G-01's 24-hour rule is normative and both implement it: an uploader may `blobGet` its own completed upload for 24 h even if nothing references it, with `space` set to any space it can read. |
| D4 | base64url (W-17, W-27) | Unpadded, URL-safe alphabet, canonical: the unused trailing bits are zero. Anything else is `invalid` wherever base64url appears (keys, sigs, blob parts). |
| D5 | Follow/subscribe of a missing space (new W-48) | Answer at once (`not_found`/`moved` per D1). Clients and executors MUST retry with back-off; they MUST NOT treat it as final. |
| D6 | Verifier key ids (W-10) | Verifiers take the server key from `/.well-known/han` by the receipt's `homeKey`; no fixed key id. |
| D7 | WebSocket path (W-07) | The generic binding listens at path `/han`; `/.well-known/han`'s `sequencer` is the full URL including `/han`. Docs and examples use it. |
| D8 | `blobPut` failures (W-27) | A part that leaves a gap or overlaps with different bytes: `invalid`. On completion with a hash mismatch: `invalid`, and the uploader's parts for that ref are discarded. `{have, complete: false}` only for a valid partial upload. |
| D9 | `hello` limits (new W-49) | `hello.ok.limits` carries every `Limits` field in han.ts, including `maxClockSkewSeconds`. |
| D10 | `signal` with `from` (W-23) | `from` is accepted only on a connection authenticated as a server actor `@:S` relaying for its own users (G-04); on any other connection it is `invalid`. |
| D11 | `hello` errors (W-03) | Unknown actor: `not_found`. Bad proof or revoked key: `denied`. |
| D12 | Challenge (W-01) | 32 random bytes, base64url (43 characters); single use; expires after 60 s. The proof's signed bytes are as the spec's §3 states; the spec agent writes them out byte by byte. |
| D13 | `.well-known` documents (new W-50) | `/.well-known/han`: `{server, sequencer, keys: [{keyId, publicKey, from, until?, compromised?}]}`. `/.well-known/han-peers`: `{peers: [{server, url}]}`. |
| D14 | Claim field `settled` (new W-51) | Present on every claim in the state view: `true` once its outcome or a resolve settled it, else `false`. |
| D15 | Golden transcripts | `interop/golden/*` become **wire conformance vectors** under `ref/wire-vectors/` with a runner that points at any server URL (`--url`), plus `probes.json`'s agreed error paths. Both implementations must pass them. |

## Added by the spec round (D16–D24)

The spec agent decides where the list above is silent. These are the items it left open; each is written into architecture.md at the place named, and the wire vectors in `ref/wire-vectors/` test the ones marked (v).

| # | Topic (gap) | Decision | Where |
|---|---|---|---|
| D16 | Test mode (D15) | A server under test runs in **test mode**: ServerName `a.localhost`, a frozen clock (wall `2026-01-01T00:00:00Z`, steady 0), the server key and actors of `ref/wire-vectors/config.json` provisioned, empty data directory. The flags that do this are the implementation's. The stock CLIs cannot (Python has no clock option; the TS CLI provisions nobody and has no clock option), so `ref/run_wire_vectors.py --launch` uses `interop/py_host.py` and `interop/ts_host.mjs`. Implementation agents: a `--test-clock T` option and, for TS, a provisioning option on the real CLI would let `--url` run against the stock binaries. | G-11 |
| D17 | Profile-space policy (W-11) | A sequencer SHOULD write one fixed PolicyDoc into every profile space (`visibility public`, `join closed`, `maxDelegationDepth 0`, `launchWindow 30`, `extensionsMinRole owner`, sessions `nobody`, modes `["auto"]`, no approvals or budget); content `{name: <ActorId>}`. Verifiers accept any valid PolicyDoc, because Policy never reads it for profile spaces (always readable, P-03). The Python `register` currently writes `default_policy(visibility public)`; either is valid, the TS one is the SHOULD. | §4.3 |
| D18 | Order of verdicts (W-14, W-45, W-47, W-18) | dedupe, routing, shape (`invalid`), rate limit (`limit`), profiles (`unavailable`), signature (`invalid`, unknown keyId `denied`), Policy (`denied`/`invalid`), and only then the moment-dependent `unavailable` (R-16, R-03a clock, R-08 durability). A doomed entry is never `unavailable`. `retryAfterMs` is the larger remaining wait. `Entry.time` is not checked by a sequencer. | §4.1 |
| D19 (v) | Signals (W-22, W-24, W-26) | Signals are delivered only on `subscribe`, never on `read` with `follow`. A signal goes to every subscription that may read the space at its head except those on the sender's own connection; body ≤ 64 KiB; no read right `denied`; missing space `not_found`/`moved`. A stranger's `subscribe` to a profile space gets records only. | G-04, G-09 |
| D20 (v) | `blobGet` errors (W-29) | No access or no supply is `not_found` (never confirms existence); a `ref` matches by `hash` and `size`; `offset` > size `invalid`, `offset` = size empty, `length` clamped to `maxBlobRangeBytes`, `length` 0 `invalid`; bytes missing though supplied `unavailable`. | G-01 |
| D21 (v) | `stream`/`watch` (W-31, W-32) | Codes and check order in G-05. A `watch` whose right is removed or whose session closes stays open and silent (both servers already did; the log tells the watcher). | G-05 |
| D22 | `han-peers` meaning (D13 consequence) | `url` is the peer's `/.well-known/han` document. Servers still keep the key sets they verified with, but no longer serve them as `{server: keys}`; a verifier compares against the peer's own document and its retained copies. `/.well-known/han` `from` of the test key is `1970-01-01T00:00:00Z`. | §4.3 |
| D23 | Executor wire duties (W-34…W-43) | X-02…X-12 as amended: the elapsed-clock reading is taken once before the first attempt; claims are built from `read {state: true}` or by folding; `refused` journal state; evidence document shape; X-12 retry of follows and cost reporting. | §4.5 |
| D24 | `hello` failure (W-03) | A failed `hello` consumes its challenge: the connection stays open and unauthenticated, every later `hello` on it is `denied`, the client opens a new connection. A server actor `@:S'` of another server authenticates with the keys in S''s `/.well-known/han`. | G-08 |

**Note on D2.** The harness probe P09 expected a reply on id 7 for a frame that is JSON but not I-JSON (`after: 0.5`). D2 says such a frame is answered with id 0, `invalid`, and the connection is closed; the vector `D2a` follows D2. A request frame that is an I-JSON object but malformed (extra member, no `args`, bad `call`) is answered `invalid` on its own id (`D2b`, `D2c`). **Note on D12.** The generic binding's challenge expires after 60 s; the Matrix HTTP read's separate challenge (`GET challenge`, §8.2) stays at 120 s.
