# Decisions for round 25

From the round-24 review (74.7, defects J1–J10). Theme: **P-15 at about half its length.** The reviewer's verdict was that P-15's complexity keeps producing G1-class holes; this round removes state instead of patching it. All agents follow these; where one is silent, the owning agent decides and writes it down.

| # | Topic | Decision |
|---|---|---|
| K1 | **The guard is the operator (J9)** | An agent's guard is always its operator from the profile pinned for the entry (P-01). `held` and `guarded` become **sets** of actors; `session.guard` and `effect.guards` store nothing that can be derived. `guard_status(state, ctx, actor)` returns `{guard, held, guarded, forced}` with `guard` = the pinned operator (absent for humans and unconfirmed operators). No precedence rules. An agent whose operator is unconfirmed or holds no role cannot be guarded or forced: instructions that would need its guard are `denied` (as today for forced spaces). |
| K2 | **One staleness scalar (J1)** | `lastOutside[X]` = the seq of the newest outside instruction (a steer into X's session, a `task` naming X, an `effect.propose` naming X as executor) received while X is guarded or forced; when X becomes guarded, it is raised to the newest unfinished outside instruction naming X. A release (`agent.release`) is `denied` iff `lastOutside[X] > seen`. Finishing, cancelling or closing the instruction never lowers it. `outside`, `cleared` and `pending_outside` go away. Vectors: the reviewer's J1 repros (held BOT closes the task; the outsider cancels the effect) plus the round-23 G1 vector. |
| K3 | **No stored readiness (J3)** | The phases `awaiting-approval` and `ready` merge into one phase **`open`**. Whether a claim may proceed is decided only at claim time by E3 (approvals in hand, the guard's included, if X or the executor is held or guarded at the claim's seq). The re-arm test, `add_guard` and every phase flip on hold changes go away. The state view gains nothing; an executor that wants to know whether a claim would pass calls `state {effect}` and applies E3 itself, or simply claims (a denied claim is cheap). Pin the reviewer's s3/s4 and fuzz seed 1248 as vectors. |
| K4 | **Approvals bounded (J2, J10c)** | Fold drops unconsumed approvals whose `expiresAt ≤ ctx.time` whenever any entry touches the effect; the cap (`MAX_OPEN_APPROVALS`) counts every unconsumed approval. The cancel right lapses with the approval. Vector + mutation. A fuzz assertion bounds the JCS size of every state item (effects, tasks, sessions, roles…) by a derived constant, so "an item that cannot fit" is shown impossible, not asserted. |
| K5 | **Guard model independent of Policy (J4)** | The ghost records the seq of every outside instruction since the last release and checks `seen` against that, not against a copy of Policy's computation. Add the move "a held agent finishes or cancels its own outside work". Re-run depth 4 (with mutations), depth 5 once under the 6 GB cap, and **model_check** on the round-25 Policy (J6), adding an attempt-limit property. Logs committed. |
| K6 | **`hello` limits (J5)** | `maxAttempts` leaves `Limits` and becomes a Policy constant (han.ts `PolicyConstants`, next to `MAX_OPEN_APPROVALS`/`MAX_OPEN_SESSIONS`); `hello` keeps exactly ten members. |
| K7 | **Agent selector (J7)** | `state {agent}` (a fourth selector, exclusive like the others; `at` may combine with it) returns `{space, head, home, policy, agent: {held, guarded, lastOutside}}`, never cut. Hosts use it plus their own profile cache instead of paging the whole state. |
| K8 | **Every count derived (J8)** | §9 depth ledger, §11, README, coverage.md: every count of calls, functions, kinds, properties, mutations and "last run" rounds is a sync_docs marker or is deleted. The interop "last run" round is derived from interop/RESULTS.md. |
| K9 | **Small items (J10)** | P-16 claim row in code order; the Matrix room-event metadata (`{id, kind, author, seq}`) stated as a §7.5 trade-off (authors and kinds of entries are visible to room members P-02 may exclude) — or hash the author with a per-space salt if that is simple; the spec agent decides and writes it down. |
| K10 | **Stronger differential fuzz** | `ref/fuzz_diff.py`'s generator gets several operators (separate from owners), operator confirm/withdraw, forced spaces, stale `seen`, held agents finishing their own work, and defaults to ≥ 2,000 seeds × 250 steps (keep the run under ~5 min; batch more seeds per node call if needed). Fold the reviewer's P-15 generator ideas in. |
