All agents follow these. Where one is silent, the owning agent decides and writes it down. N3, N6, N7 and N8 are handled separately (pinning exactness, one `now`, executor cost wording, tooling) and are not part of this file.

| # | Topic | Decision |
|---|---|---|
| P1 | **Who is guarded** | X is **guarded** if it chose to be (it opened a `guarded` session: X joins the set `guarded`; this is sticky) or it is **forced** (`forceGuarded` is on and the profile pinned for the entry says X is not human; nothing is stored). X's **guard** is the confirmed `operator` in the profile pinned for the entry; humans have none. `guardStatus(state, ctx, X)` returns `{guard?, guarded, forced}`. `held`, `lastOutside` and `seen`'s P-15 role are gone; `seen` stays only if something else needs it (decide and write down). |
| P2 | **Guarding is recorded on the work** | Every effect and every task carries `guardedFor`: a list of agents whose guard must approve its effects, fixed when it is created and never shrinking. **Task:** `guardedFor` = the parent task's `guardedFor`, plus the author if the author is guarded at that seq. **Effect** (`effect.propose`): `guardedFor` = the named task's `guardedFor`, plus the proposer if guarded, plus the executor if guarded, all at that seq. Switching `forceGuarded` off, an unguard, or an operator change never frees recorded work. Bound: `maxDelegationDepth` + 2 agents (state the derived constant). |
| P3 | **Delegation keeps the guard** | A guarded agent may `task` other agents. Their effects for that task (and its subtasks) carry the delegating agent in `guardedFor`, so they need its guard's approval. That is the user's "allow delegation". Steering others is not delegation: a guarded agent may `session.input` only into its own sessions. |
| P4 | **Claim (E3)** | Besides any approval rule, a claim needs, for each agent A in `guardedFor` ∪ {proposer, executor, each if guarded at the claim's seq}, an unconsumed, unexpired approval by A's guard (pinned at the claim), signed with a valid key, while the guard holds a role. An A with no confirmed operator can't be claimed for. Guards are exempt from `separateApprover`, and one approval by a guard who is also a rule approver counts for both. `relevantActors` lists every A, and the guards from their pinned profiles (the M3 loop is unchanged). |
| P5 | **What a guarded agent may not do** | `effect.approve`, `member.set`, `policy.set`, `redact` of others' entries, `agent.release`, and `session.input` into sessions not its own are `denied` while X is guarded. Everything else is allowed, including `task`, `effect.propose`/`claim`/`outcome`/`resolve`/`cancel`, its own sessions, `message`, `task.update`/`task.cancel`. The decide rule is one line: "a guarded author may not approve, govern, unguard, redact others or steer others". |
| P6 | **Unguard** | `agent.release {agent}` (no `unguard` flag, no staleness) is authored by X's guard while the guard holds a role, and removes X from `guarded`. It frees nothing already recorded (P2). Rename the kind to `agent.unguard` only if the kind count and wire stay simpler; decide and write it down. |
| P7 | **Instructions to guarded agents** | Outside instructions are no longer `denied` for lack of an operator: they are inert, since nothing they cause can be claimed without the guard. Keep the denial only if a concrete attack needs it; write down which. R-24: a host runs every turn driven by an instruction whose author is neither X nor X's guard in the stricter mode. Once such an instruction has entered a guarded agent's session context, every later turn of that session runs strict (a host duty; no log state). |
| P8 | **State and wire** | State loses `held` and `lastOutside`; effects and tasks gain `guardedFor`. PAGED and the cursor shrink accordingly. `state {agent}` returns `{space, head, home, policy, guarded}` cut to the agent, which is the `GuardInput`. han.ts, §3, §5 and the wire vectors follow. |
