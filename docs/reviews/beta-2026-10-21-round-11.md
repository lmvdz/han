## Implementation findings

The mapper now recognizes `_meta.terminal_output_delta`, preserving complete-content, legacy and raw-output precedence. Delta updates append without deduplicating repeated text. Complete snapshots replace accumulated output instead of appending a duplicate.

Streamed tool text is withheld until completion or failure, then masked as one assembled unit. This avoids publishing a secret prefix before a later delta completes the masking pattern. A final delta is incorporated before terminal publication. Per-update and aggregate truncation suppress the incomplete output with an omission notice, avoiding masking across noncontiguous fragments. A later complete snapshot can recover the content, while the terminal publication gate remains in force.

Both host event paths apply the update before consuming terminal signals. Test-count interpretation reads the complete, uncut terminal result rather than the final delta alone. The integration fixture splits both a secret-shaped value and a test summary across updates, then checks masked Node API output and the resulting Board counts.

No new concrete correctness defect was found. The deliberate tradeoff is that running streamed tools do not expose incremental output; long-running work can remain less observable until it ends. The live `mcp.han.propose` item still has empty content, so terminal-output recovery should not be described as universal tool-result visibility.
