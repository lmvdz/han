## Implementation findings

The parser recognizes the adapter's `rawOutput` envelope containing both `result` and `error`, including null values, without requiring repeated `rawInput.server/tool`. It extracts only declared text blocks and the error message. Structured content, embedded resources, binary payloads and diagnostic data are not copied into shared output. Existing rendered output takes precedence, and MCP progress messages are not treated as contiguous result deltas.

Results enter the existing snapshot, masking and size-limit handling. The integration fixture splits a secret-shaped value across result text blocks, checks masked proposal and failure text through the Node API, preserves the failed status and rejects opaque fields. A separate regression checks that oversized MCP output is omitted rather than publishing an incomplete secret prefix.

No new concrete correctness defect was found in this correction. Completed calls delivered only as initial `tool_call` replay events still lose output; this change handles completion updates, not every result shape. The earlier streamed-terminal tradeoff also remains: incremental output is withheld until completion or failure.
