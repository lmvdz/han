## Implementation assessment

Before opening guided setup on Linux, the launcher checks `pkcheck` and asks polkit whether `dev.han.approve` is registered. A missing action has a supported installation path through administrator authentication, or `han setup install-presence` run by an administrator. The installed policy retains `auth_self` confirmation. Headless `--no-tui` startup does not install the action or disable presence. Registration does not establish that a desktop authentication agent is available; the documentation states that prerequisite.

The installer preserves differing administrator policy and publishes a complete file without replacing a concurrently created destination. On Linux the temporary file starts with mode 0600 before content is written, then becomes 0644 before publication. A dangling destination symlink is not followed into a new target. The doctor and launcher use the registered action rather than requiring one particular administrator-selected filename. These are bounded corrections to the previous refusal, not a new claim about credential isolation or authorization coverage.

The stale-address fix supplies an explicit initial home ticket to `Node::start`. Parsing and address validation precede database work; the pin is persisted before saved pins are loaded and before any links or ticker are spawned. Both the person-node CLI and host/executor role startup pass their supplied ticket through this path. Startup therefore does not first open a link using the old saved port. Ordinary starts without a supplied ticket retain persisted-pin behavior.

This deliberately avoids live replacement of an already-running link. Runtime `HomePin` link replacement, cancellation of detached callbacks and key-cache races during arbitrary live repinning are not addressed or credited by this patch. The regression concerns restarting the same home identity on a different port, replaying its retained queued request and creating a fresh space afterward.
