## Prioritized findings

1. **P1 — Deliver one guided setup and a real Trusted team preset.** `docs/getting-started.md` requires separate home, key/profile, node, space, agent, executor and teammate operations. Searching the CLI found no onboarding/preset implementation. Provide repository selection, explicit grant preview, resumable setup, login, and automatic landing after configured checks within that grant. Preserve advanced configuration. Then time an unfamiliar user's first useful task through landing and a teammate's join; ordinary setup belongs inside the clock.

2. **P1 — Let users create and start useful tasks through supported product controls.** `apps/han-faces/src/task.rs` exposes only List and Cancel. The live task was created by `create-task.py` through RPC. Add task creation and selection/start to the TUI, with a supported CLI equivalent. Accept a fresh repo task through checks and landing without custom scripts.

3. **P1 — Turn recovery coverage into independent operational acceptance.** The live run had author assistance and an existing runner. Exercise interrupted model turns, host/node/executor restart, lost effect replies, failed/missing checks, conflicting edits and exhausted quota with retained work. Make each recovery actionable from the TUI. Do not equate fake-harness tests with two real users or real-harness recovery.

4. **P2 — Doctor must check launchability under the configured agent identity.** `apps/han/src/doctor.rs` gathers runtime health using `r.node.exists()` and adapter directory existence. These do not prove the configured OS user can traverse and execute the runtime. The initial shared-runtime incident demonstrated the resulting false reassurance. The source placement fix and reported OS-user verification address this instance, but doctor still needs an identity-aware diagnostic and retained regression reproduction, including already-installed broken records.

5. **P2 — Surface gate fidelity and unknown cost explicitly.** The Codex driver honestly declares `prompt_only` and its isolation gaps. `spec/profiles/han.status-1.md` requires faces to show gate and sandbox, whereas `apps/han-tui/src/ui.rs` displays sandbox fidelity and `Sandbox` in `crates/han-node/src/api/rows.rs` has no separate gate field. Align implementation/types/spec so enforced outer isolation cannot be mistaken for every-call gating. The recorded subscription metric cost 0 is unmeasured, not evidence of free use: show unknown/unmeasured distinctly. No boundary escape or false completed-task outcome was established from these presentation gaps.

6. **P2 — Retain and resolve the live usability anomalies.** The evidence records a no-issue session showing an issue-claim overlap, an excessively long proposal title derived from the task ask, initial missing Git identity, and roughly 999 status sequence updates in 100 seconds. These observations need deterministic reproductions before severity is asserted. Prioritize incorrect overlap information because it directly harms team coordination.
