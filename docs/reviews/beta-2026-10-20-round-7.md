## Implementation assessment

The TUI returns a typed continuation only after a confirmed space response and explicit Enter. Queued or uncertain creation stays in recovery; remembered board selection is not permission to provision. The terminal reader is stopped and joined before the CLI takes input or starts login. The final task form is prefilled without submitting it; ordinary explicit task submission remains the action that starts work.

The workflow journal retains choices rather than credentials, validates its schema and plan, and is guarded against concurrent foreground setup. Subscription harness aliases are canonicalized before saving. The continuation checks that the person node and local space are live, writes are settled, the person currently owns the space, and the policy exactly matches the Trusted preset. Remote-home membership does not authorize local provisioning. API-key harnesses, Windows local continuation and advanced policies use the separate advanced path.

The flow uses the existing installation, enrollment, login, executor provisioning, check configuration and finish-policy operations. Queued membership or operator confirmation is not reported as ready. Initial executor configuration is checked with the production diagnostic path, including the GitHub App check. An enabled resume compares the saved configuration instead of rewriting a running executor. A child independently rechecks live ownership/policy and configuration before opening its executor.

Readiness comes from the live child's pipe after role startup, configuration construction and executor opening, not a historical Board session. A failed child leaves the home/person running and does not automatically consume another retry. A healthy child may acknowledge a new foreground generation; a child still starting cannot consume it. This is process readiness, not proof of current subscription quota, a completed model turn or a successful landing.

Managed control stop first asks the child to stop and waits while the home can still accept outcomes, then stops the home/person. The executor permits a bounded seven-second drain; the supervisor checks child exit status, and the outer CLI deadline covers the coordinated stop budget. Pre-stopped executor and lane loops do not begin recovery or a new pass. Ctrl-C still requests process-wide concurrent shutdown, and a forced/failed drain remains a recovery case. CLI `stop` confirms the process stopped, not that every in-flight effect settled successfully; failure details remain in logs.

Pre-merge review found and corrected the historical-session readiness deadlock, startup validation bypass, unpolled work beginning during drain, home shutdown preceding settlement, retry-generation loss during startup, discarded child exit failure, timeout mismatch and harness-alias mismatch. These corrected findings are not counted as remaining blockers. The review also prompted correction of stale installation and guided-continuation documentation. The author reports that the Windows process test found a stack overflow; source inspection confirms the continuation is now boxed, and this reviewer independently reran the passing final process tests. None of these fixes substitutes for running the complete real-user flow.
