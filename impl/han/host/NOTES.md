# han.host: spec gaps and the readings taken

1. **State at the input's receipt (R-24).** The host reads `state {agent, at: seq}` (K7), the agent's guard facts after the steering input's record, not the head (`Host._state_at`; the whole state is read only for sessions and tasks, `Host._full`), with the agent's profile as that receipt pinned it, and asks `P.guard_status` (R-24, H8); there is no effective mode. If that read fails it runs the turn strict. So a steer that was outside input to a guarded agent stays strict even if owners re-allow `auto` and the guard releases before the host runs (test_host_ce.py).
2. **Strict-mode rule used** (`Host._mode_for`): strict if held (every turn); else if `guard_status` on the state at the instruction's seq says guarded or forced and the author is neither the agent nor its guard (an unconfirmed operator means no guard, so everyone else is outside); else if the turn carries another session's stream as data (R-24 SHOULD for everyone, MUST when guarded; implemented as always); else auto. The guard's own steer is not "outside input" (P-15 exempts it from holding); R-24's "outside input in `guarded` mode" does not say whether the guard counts.
3. **Effects naming the agent as executor** are listed in R-24 as instructions that make a turn strict, but an executor is an `han.exec` actor, not a host. The host does not turn them into turns.
4. **"Waits" in strict mode.** The host does not block on the proposal (8.4: no blocking); it publishes `proposed <action> as <id>` and goes on. Both modes propose.
5. **Task turns**: the task's `ask` is the text; the turn's proposals carry `task` in the body. A budgeted space needs `cost` and a budgeted task (P-05); in a budgeted space the host attaches `cost` (the action's own `World.cost`, else the default from `--cost UNIT:AMOUNT`) and names an open budgeted task assigned to it (the turn's task if it qualifies, else one with enough left). If there is none, or no cost in the space's unit, it proposes nothing and says `refused: <action>: cannot spend, ...` in its stream. Tasks get no `task.update` from the host (what an agent owes a task is unspecified).
6. **Reporting refusals as data.** A held agent's Task/Steer is not appended; it becomes an `output` item "refused: ..." (and `host.refused`). A `message` would be allowed while held but is noisier and is itself data to readers. A Policy denial of a sent intent is reported the same way.
7. **Crash safety (R-18).** Decision and cursor move are one SQLite transaction; entries are signed before they are stored, so a replay sends the same entry (R-01 dedupe, client outbox) and cannot propose twice. A crash before that transaction re-runs the turn (nothing was proposed). Residual: `say` intents and status items are not exactly-once (a crash between sending an output item and settling it repeats the item with the next `n`); outputs are not intents.
8. **`seen` and `refs`** (R-17): `seen` = receipt seq of the instruction, `refs` = the instruction id plus the ids of data records read for the turn (at most 64). Stream items read as data have no record id, so they cannot be cited; the host keeps them only in the turn input.
9. **Context requests** arrive as a signal `{type: "han.context.request", session}` (rate-limited to one per second). Signals are never authority, and the request only publishes a snapshot the sequencer then filters by the read right; not in the spec. Per sequencer NOTES 17, readers fetch the context blob with `blobGet`.
10. **Plan shape** for a World action: `{action, target (url/target/path arg, else the action name), args}`; `repeatable: false`; no `cost`, `expiresAt`.
11. **Session ownership.** The host opens one session per journal (`steerMode` = `--mode`) and recovers its id from the journal's `open` intent. It does not reopen after `session.close` by an owner.
12. **ClaudeCodeAgent** now runs against the real SDK (claude-agent-sdk 0.2.165, bundled Claude Code 2.1.294; the SDK prefers its bundled `claude.exe` over the installed 2.1.296). `tests/test_host_claude_live.py` (HAN_LIVE=1) and `demo/claude_demo.py` are the live evidence; `test_host_claude_gate.py` covers the rest with a fake client. Driver = `han/host/agent.py`, tool gate = `han/host/claude/gate.py` (pure). Where §8.4 and the real SDK/Claude Code differ:
    - **`canUseTool` is not called for every tool call.** The SDK calls it only when the CLI's rules say "ask". Read/Glob/Grep inside cwd (any mode) and edits inside cwd in `acceptEdits` never reach it (observed: the auto-turn `Write notes.txt` left no trace). Since round 20 a `PreToolUse` hook (`hooks={"PreToolUse": [HookMatcher(matcher=None, ...)]}`, `ClaudeCodeAgent._pre_tool_use`) asks the Gate for EVERY call: allowed calls return `{}` and continue through the CLI's own flow, denied and world calls return `permissionDecision: "deny"` with the reason (for a world call the host's "proposed as <id>" answer, proposed once). `can_use_tool` stays as the second line for calls the CLI still asks about (it re-decides without a second trace entry). Unit-tested with a fake client that plays the hook first; not exercised live (no API calls were made).
    - **"No allow rules" is not enough to make "every tool except the read-only file tools" reach the callback**, for the reason above; in `default` mode a Write in cwd does reach it (allowed by the gate), in `acceptEdits` it does not.
    - **Streaming input mode**: `ClaudeSDKClient` with a string `query()` per turn; `permission_mode` is switched with `set_permission_mode` before each query. The conversation continues across turns in one CLI process (the model remembered the earlier deploy). `max_turns` is per query, not cumulative.
    - **A world action is answered in a denial.** The only way to answer a tool call from `can_use_tool` without running it is `PermissionResultDeny(message)`; the model sees it as a failed call with that text ("proposed as <id>, waiting for <guard>") and, in the runs seen, explained it correctly to the user. The id is real: the host signs the `effect.propose` inside the callback (`Host._propose_now`, a small edit to host.py) and appends it after the turn is journaled, so the entry appended is the one named. A refusal (no executor, budget) answers "refused: ...".
    - **The declared tool `deploy`** is an in-process SDK MCP server (`han`, tool name `mcp__han__deploy`) whose handler is never run; `http_post` likewise. Their parameters map to the plan: `deploy {target, content}` is action `file.write` (target relative path, content text); `http_post {url, body}` is `http.post`. `strict_mcp_config=True` and an explicit `mcp_servers` mean no external server loads, in both modes (not only strict turns). `tools=[Read, Write, Edit, Glob, Grep, Bash, WebFetch, WebSearch]` removes the rest (Task, TodoWrite, ...) from the model's context; a custom `system_prompt` replaces Claude Code's (about 13k input tokens per turn, mostly cache reads).
    - **No Bash sandbox on Windows.** The SDK's `sandbox` is macOS/Linux only, so §8.4's "the session runs sandboxed" does not hold here and `guarded` is advisory for anything a shell can do. The gate's substitute: a command that names the network (curl, wget, ssh, git push, pip install, any scheme://, ...) is a World action `bash.network` (nobody executes it; an executor must opt in), a heuristic that a determined model can get around, e.g. `python -c` with sockets is caught only if it spells a scheme or a listed word; in strict turns every other Bash call is denied; in auto turns only one plain command from {ls, dir, pwd, cat, type, head, tail, wc, echo, date, sort, uniq, mkdir, touch, grep} with no shell syntax and no path outside cwd. File tools and Bash are the only local power; WebFetch/WebSearch are proposed, not run. The model API is the only egress the gate allows, but that is enforced by nothing at the OS level. Per §8.4 the host says so in its `status`: when the agent is not sandboxed (`Agent.sandboxed`, False for every driver here) the `status` items of a guarded session carry `detail: "guarded: advisory (no sandbox)"` (`Host._emit`; guarded = the host's `--mode guarded` or the session's effective mode). Error statuses keep their own detail.
    - **Output is not streamed mid-turn.** The driver returns its Say actions at the end of the turn and the host emits them as `output` items then (journaled, so exactly-once-ish); partial messages (`include_partial_messages`) are not used. Per-tool status items and OSC 7501 reports are not emitted.
    - **Cost/turns**: `ResultMessage` (num_turns, total_cost_usd, usage) is kept in `ClaudeCodeAgent.results`; an error result (e.g. max turns) becomes a `[claude stopped: ...]` Say.
    - Still not done: the `watch` MCP tool (reading others' sessions) and the periodic context item; both left to the operator.
    - **Bash gate (F6).** Every glob character (`*?[]{}`), `$`, backticks, `!`, `~` and the rest of the shell syntax is refused in every mode; an allowed command runs as `set -f; <command>` (the hook returns `updatedInput`, `can_use_tool` allows with `updated_input`; the gate accepts its own prefix back). Tested with the grader's symlink repro (`cat lin[k]`). Not exercised live.
