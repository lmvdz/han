# han.host: spec gaps and the readings taken

1. **State at the input's receipt (R-24).** The spec says the host re-reads the effective mode "from the state at the input's receipt". The wire has no read of past state (`read state:true` gives the head), so the host uses the head state after the record. Holds persist and modes only tighten, so this is stricter or equal, except when the guard releases between the steer and the host's read (then the turn may run looser than at the receipt). Needs `read(..., state=true, at=seq)` or a local fold with pinned profiles (receipts carry only profile seqs).
2. **Strict-mode rule used** (`Host._mode_for`): strict if held (every turn); else if the session's effective mode is `guarded` or the agent is guarded now, and the author is neither the agent nor its guard; else if the turn carries another session's stream as data (R-24 SHOULD for everyone, MUST when guarded; implemented as always); else auto. The guard's own steer is not "outside input" (P-15 exempts it from holding); R-24's "outside input in `guarded` mode" does not say whether the guard counts.
3. **Effects naming the agent as executor** are listed in R-24 as instructions that make a turn strict, but an executor is an `han.exec` actor, not a host. The host does not turn them into turns.
4. **"Waits" in strict mode.** The host does not block on the proposal (8.4: no blocking); it publishes `proposed <action> as <id>` and goes on. Both modes propose.
5. **Task turns**: the task's `ask` is the text; the turn's proposals carry `task` in the body. A budgeted space needs `cost` and a budgeted task (P-05); the host never sets `cost`, so such proposals are denied by Policy and reported in the stream. Tasks get no `task.update` from the host (what an agent owes a task is unspecified).
6. **Reporting refusals as data.** A held agent's Task/Steer is not appended; it becomes an `output` item "refused: ..." (and `host.refused`). A `message` would be allowed while held but is noisier and is itself data to readers. A Policy denial of a sent intent is reported the same way.
7. **Crash safety (R-18).** Decision and cursor move are one SQLite transaction; entries are signed before they are stored, so a replay sends the same entry (R-01 dedupe, client outbox) and cannot propose twice. A crash before that transaction re-runs the turn (nothing was proposed). Residual: `say` intents and status items are not exactly-once (a crash between sending an output item and settling it repeats the item with the next `n`); outputs are not intents.
8. **`seen` and `refs`** (R-17): `seen` = receipt seq of the instruction, `refs` = the instruction id plus the ids of data records read for the turn (at most 64). Stream items read as data have no record id, so they cannot be cited; the host keeps them only in the turn input.
9. **Context requests** arrive as a signal `{type: "han.context.request", session}` (rate-limited to one per second). Signals are never authority, and the request only publishes a snapshot the sequencer then filters by the read right; not in the spec. Per sequencer NOTES 17, the context blob is not fetchable by readers through `blobGet` in the generic binding.
10. **Plan shape** for a World action: `{action, target (url/target/path arg, else the action name), args}`; `repeatable: false`; no `cost`, `expiresAt`.
11. **Session ownership.** The host opens one session per journal (`steerMode` = `--mode`) and recovers its id from the journal's `open` intent. It does not reopen after `session.close` by an owner.
12. **ClaudeCodeAgent** is written against the installed SDK (`ClaudeSDKClient`, `set_permission_mode`, `can_use_tool`, `setting_sources=[]`) but never run. Sandboxing, the `watch` MCP tool and MCP lockdown for strict turns (8.4) are left to the operator/not implemented.
