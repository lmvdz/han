# History

This repository starts at its first public commit. The work before it was not under version control. Dates before the first commit come from the files' own modification timestamps and are stated as such, not as verifiable proof.

## v1 rounds (2026-10-10 → 2026-10-11)

HAN was first published as v1 round 6 (tag `v1-draft-r6`). In round 7 its scope narrowed to the part that is new: making agent actions safe. Federated chat is left to networks like Matrix that already do it well.

Each round was graded by a fresh, independent reviewing agent against the same fixed rubric ([grading-rubric.md](grading-rubric.md)), with no stake in the score.

| Round | Independent score | What changed |
|---|---|---|
| 1 | 57.8 | v1 core: one primitive (signed entries in a per-space log), six calls, federation by mirroring |
| 2 | 69.5 | Claim-as-fence executor protocol; redactable content separated from the permanent header; reference Policy, conformance vectors, model checker |
| 3 | 73.1 | Revocation and budget fixes; real-Ed25519 wire layer; head gossip; notices; the model checker found a deadline-ordering defect |
| 4 | 71.6 | Simpler budgets; deadlines measured on the executor's own clock; fold-totality fuzzer, which found a budget-accounting defect |
| 5 | 74.1 | Forced takeover after home death removed from the core (forks instead); window pinned in each claim; per-space blob supply; content validation |
| 6 | 76.6 | Abandon margin proven for two-sided clock drift (model with clock rates); signed move acceptance; signed redaction proofs; private gossip; signal relay |
| 7 | — (graded with 8) | **Repositioned as the agent-safety layer over existing chat transports (Matrix first).** Chat, presence, files and invites move to the transport, and the core shrinks to the sequencer (3 calls), Policy, Identity, verification and the executor. Fixes: claims state their window, owners are human, operator withdrawal is checked at claim, abandon needs elapsed sequencer time, assignees can't close tasks with running effects. |
| 8 | 67.8 | **Live sessions.** `session.open`, `session.input` and `session.close` put live work in the log as authority (who may watch, read and steer, set per space by owners), while the stream itself rides the transport (T-07, Matrix threads and MatrixRTC). Steering is signed and sequenced. A session can make outside steers `guarded`: the harness's stricter mode for that turn, and the effects they trigger wait for the session's own human (P-15, R-24). Text read from other sessions is data, never instruction. |
| 9 | 67.5 | **Taint replaces steer tags.** Round 8's guard depended on the steered agent tagging its own proposals, so it could be dropped or laundered through another agent (review round 8). Now an outside steer into a guarded agent session taints the agent in the log; tasks and relayed steers carry the taint; every effect the agent proposes needs its human, whose approval is checked like any other (role, key, expiry). Owners may restrict steer modes. T-07 gets a `StreamItem` type and binding calls; the Matrix binding uses per-right E2EE rooms. §8.3 restores the generic binding's rules as G-01…G-05; §8.4 profiles Claude Code; coverage.md rewritten. |
| 10 | 69.8 | **Holds replace taint.** Review round 9 (67.5) laundered taint through tasks the assignee didn't name, agents without a guard, approvals by tainted agents, and accidental clears. Tracking influence through the log kept leaking, so round 10 removes the channel instead: an outside steer into a guarded agent session puts the agent **on hold** for its operator. While held it may talk, report and propose (each proposal waits for the operator), but may not delegate, relay, approve or govern. Only an explicit release by that operator ends the hold. The guard always has the steer right on its agent's sessions; restricting allowed modes applies to open sessions; the Matrix binding uses two E2EE rooms per session with stated power levels; §8.4 uses the Agent SDK's permission callback and an egress sandbox. The guard model gains two operators and a second property, with all 12 mutations caught by a property. |
| 11 | 69.2 | **Holds tightened.** From review round 10: owners can make open sessions stricter but never looser (no allowed mode at least as cautious → the session is dead); a guard's rights need it to hold a role, and an owner may release an agent whose guard is gone; `suggest` no longer holds (it never reaches the model); held agents may cancel their own delegations; one open approval per author, and the guard is exempt from the 16-approval cap. Matrix: the publishing host encrypts to current rights and rotates keys on removal. §8.4 lists sandbox egress, no allow rules, and how WebFetch and MCP are handled. Guard model: four properties, 15 mutations. |
| 12 | 71.1 | **P-15 simplified.** Two modes (`auto`, `guarded`); `suggest` was removed (showing input to the human first is host behaviour), which closes the hole where tightening to it loosened Policy. One hold rule per agent: an outside steer into any session of an agent with a live guarded session holds it, so an auto side-session is no side door. A guarded session whose guard is gone is dead, and owners stand in for a departed guard (release, approve, cancel), so nothing is orphaned. Approvals already expired are refused, the cap counts only unexpired ones, and an author's expired approvals are dropped. One complete `TransportBinding` (7 operations). goal.md and README no longer overclaim. |
| 13 | 72.5 | **One invariant for guarded steering.** Review round 12 bypassed the guard four ways: an auto session opened before the operator confirmed, a held agent as executor, an owner evicting the guard to approve as its stand-in, and tasks. P-15 now states one invariant: while an agent is guarded, any instruction to it (steer or task) from anyone but its guard holds it; while held, nothing it proposes or is named executor of runs without the guard's own approval; only the guard ends a hold. The guard is the agent's guarded session's, not the steered session's; nobody stands in for a guard. A new approval supersedes its author's old one. The guard model was rebuilt from the spec's intent (not Policy's code), covers BOT as executor, tasks and owner steers, and deduplicates on content: depth 6 in about a minute, 18/18 mutations. One transport signature list. |
| 14 | 72.7 | **Guarded is sticky.** Review round 13 un-guarded an agent from outside (an owner closing its guarded session, evicting its guard, or toggling modes) and then instructed it freely, and found that naming an agent as executor was an unheld instruction. Now guarding is the agent's own sticky choice (`guarded[X]`), ended only by the agent itself while not held; owners can still force guarding through modes. Proposals naming a guarded executor are instructions. Returned approvals stay superseded. Hosts run every outside-instruction turn of a guarded agent in the stricter mode. The guard model's ghost now models the sticky choice independently; 21/21 mutations. |
| 15 | 73.1 | **One predicate, every path.** `guardedNow(X)` = the agent's own sticky choice or owner-forced through modes, used for every instruction path (steer, task, executor slot); becoming guarded with outside instructions still open holds at once; a held proposer's older proposals need its guard too, so the invariant is literal; an agent can always unguard (re-closing a session an owner closed). R-24 and §8.4 agree (MUST). The guard model's ghost is derived from the invariant sentence, with two guardable agents and multi-assignee tasks: 5 properties, 25/25 mutations. The timing-model rows are marked partial. |
| 16 | 72.2 | **Holds settle in one place.** Review round 15 found that 'becoming guarded holds at once' only worked when the agent opened a guarded session, and that effects aimed at a held executor lost their guard on release. Policy now settles holds after every entry: a guarded agent with outside work open since its last release is held, and such effects record the guard; the per-path task and executor code went away. Also: `profile` is a reserved space name (the reference crashed on it), an abandon with any key but the claim's instance leaves `unknown`, effects of a closed task can't be claimed, the model rows of §10 say plainly that the timing model last ran in round 7, and T-02 states which transport IDs v1 supports. |
| 17 | (pending) | **Before building.** Fixes the round-16 findings that an implementation would inherit: a release covers only what its guard had `seen` (stale releases are denied; newer work stays pending); agents never draw on the space budget (E6 rechecks at claim); the grammar is strict ASCII whole-string, and the reference now matches it (it accepted trailing newlines and non-ASCII digits); Matrix rejects count only from the sequencer's application-service user; R-16 after a restart; §6.4 lists the P-15 transition. Graders put the ceiling for design-only work at about 80; the next step is a minimal working reference. |
| 18 | (pending) | **Built and precise.** A minimal working reference (impl/: sequencer, client, executor, agent host, verifier, CLI; 78 tests) and a clean-room TypeScript Policy written from the spec alone (cleanroom-ts/: 111/111 old vectors after nine spec-gap fixes). Their gaps became rules: R-25 (what Log validates vs. Policy), P-16 (when `invalid` vs. `denied`, and the order of checks), and some 30 previously implicit choices, each pinned by a new vector (133 vectors, 175 mutations). Only humans create spaces. The timing model re-ran on the current fold: all properties hold, 10/10 mutations. Guarded steering is unchanged pending the user's decision on a redesign (studies/). |

The full defect lists from each review drove the next round. Defects the executable checks found on their own are listed in [architecture.md §10](architecture.md).
