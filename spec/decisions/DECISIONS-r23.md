# Decisions for round 23

From the round-22 review (74.0). All agents follow these; where one is silent, the owning agent decides and writes it down.

| # | Topic | Decision |
|---|---|---|
| F1 | **Forcing decided per instruction (review D1, D2, D10)** | Under `policy.sessions.forceGuarded`, every **non-human** actor with a role is guarded *when it is the target of an instruction* (a steer into its session, a `task` naming it, a proposal naming it as executor), with `g` = the operator in the profile **pinned for that entry**. P-01 pins instruction targets (session actor, each task assignee, the executor). A non-human target with no confirmed operator holding a role: the instruction is `denied` ("a forced space needs every agent's operator here"). The `agents` state map goes away (no fold-time snapshot). The one exemption: an actor whose pinned profile is `actorKind: "service"` is not held **when named as executor** (services execute; they don't take instructions); a service that holds a session or is tasked is forced like an agent. |
| F2 | **A release kind (review D9; simpler interface)** | New kind `agent.release {agent, seen-bound via header seen, unguard?: true}`, authored by the agent's guard. It replaces `session.input {release, unguard}`; `session.input` goes back to `{session}` only. Same staleness and role rules as today's release. Kinds: 22. |
| F3 | **Bounded state (review D3)** | (a) Fold prunes approvals that are `dropped` (keep consumed ones until their claim settles, then prune). (b) Closed sessions leave `state.sessions` at close (instructions naming a closed or unknown session are `invalid`, "no such session"). (c) A state page, and a `read {state, effect}` reply, is bounded by **bytes**: the server cuts `effects`, `tasks`, `sessions` and `roleHistory` so the item fits `maxFrameBytes`, with `next`; only `policy`, `roles` and the scalar fields are repeated on every page. (d) `roleHistory` keeps at most the last 64 intervals per actor (older reads fall back to "readable at seq k" via the record's own role checks; spell out P-02 accordingly). |
| F4 | **Read combinations (review D6)** | `effect` or `cursor` together with `at`, `follow` or each other: `invalid`. Notices are signals and are **never replayed** (a notice for an actor with no live subscription is dropped). Integers below −(2^53−1) are treated exactly like those ≥ 2^53 (G-07 (1a)). |
| F5 | **Truthful verification claims (review D5, D8, D11)** | `sync_docs` derives the guard-model depth/result and the timing-model "last run" round from `ref/logs/*` (newest complete log), and rewrites §4.5 and §10 accordingly. The "Not tested" list no longer contains the §8.2 claim. impl/NOTES item 18 corrected. |
| F6 | **Gate (review D4)** | The Bash gate refuses every glob metacharacter (`*?[]{}`), `$`, backticks, `!`, and any brace/tilde expansion, in every mode; commands run with globbing disabled (`set -f`) as a second line. |
| F7 | **Models** | The guard model stores a 32-byte hash per state (not a JSON copy) and aborts cleanly above a memory cap (default 6 GB) with a "NOT COMPLETED" line; run depth 5 once with the cap. `model_check.py` re-runs on the round-23 Policy (timing, drift, single + mutations) and its log is committed. |
| F8 | **E10 harness, part 1 (review D7)** | Wire vectors gain an **advancing test clock** (test-mode control call `test.clock {wall, steady}` accepted only in test mode) so R-16 `unavailable`/`retryAfterMs` and R-03a become vectorisable; the 1,001-task paging setup is generated, not counted as 1,141 expectations (report expectations per vector family). A second test server comes in a later round. |
