# Decisions for round 22

From the round-21 review (73.7) and the user's steering decision (2026-10-11: "only the operator loosens + per-agent forcing"). All agents follow these; where one is silent, the spec agent decides and writes it down.

| # | Topic | Decision |
|---|---|---|
| E1 | **Only the operator loosens (P-15; review D2)** | An agent's own guarded choice (`guarded[X] = g`) is set when X opens a guarded session (unchanged), but is **never** ended by X. Closing sessions no longer unguards. Only `g` ends it, with `session.input {session, release: true, unguard: true}` on any of X's sessions (the release part follows the existing release rules; `unguard` additionally clears `guarded[X]`). The old "an agent can always undo its own choice" sentence and the re-close rule go away. |
| E2 | **Owner forcing per agent (P-15; review D3)** | New PolicyDoc field `policy.sessions.forceGuarded: boolean` (default false). When true, every **agent** member X (actorKind `agent`, confirmed operator holding a role) is guarded with `g` = its operator, whether or not it has a session, on every instruction path (steer, task, executor slot). Services are never forced. Policy learns an agent's operator from the profile pinned when `member.set` gives it a role: fold records `agents[X] = operator` (state field), cleared when its role goes. The old "modes force guarding through sessions" rule stays for sessions, but forcing no longer depends on them. |
| E3 | P-15 self-contradiction (review D10) | §6.6 says what `guards_of` does: while a proposer is held, even its earlier proposals need `g`. Delete the "effects proposed before the hold are outside what Policy gates" phrase there and in README/§7.5 (keep the §7.5 row for the *agent's sandbox-local actions* only). |
| E4 | **Matrix body leak (review D1)** | A client uploads the **whole entry** (header + content) with `POST /_han/v1/entry` (HAN-authenticated; replaces `/content`) and posts only `org.han.entry {id}` to the room. The sequencer's room events are `org.han.entry {id, kind, author, seq}` and `org.han.receipt {receipt}` (a receipt reveals only ids and hashes). Headers and bodies are served only by `GET /_han/v1/read` under P-02. han.ts and §8.2 say exactly this. `unavailable` over Matrix: the sequencer posts `org.han.reject {id, code: "unavailable", retryAfterMs}` (a reject with this code is not final). |
| E5 | **One order of verdicts (review D4)** | §4.1 order, and the only order: (1) dedupe, (2) routing (`moved`/`not_found`), (3) frame/entry shape and size (`invalid`), (4) signature with the author's *pinned or cached* profile, where an unknown author's profile that can't be fetched now is `unavailable` (the only `unavailable` before Policy, and only when the verdict genuinely can't be computed), (5) Policy (`invalid`/`denied`), (6) rate limit (`limit`), (7) the moment-dependent `unavailable` (R-16, R-03a, R-08 durability). Delete contradicting sentences. ref, impl and the TS clean-room all follow it; add a wire vector per adjacent pair where observable. |
| E6 | Host state for mode (review D5) | The *effective mode* of the steered session comes from the state at the input's seq; `held` and `guardedNow` come from the **head**. R-24 says so. |
| E7 | Claude gate (review D6) | While guarded or held, Bash is default-deny except an allow-list of commands whose every argument is checked: flag values with paths are path-checked, `~` and UNC (`\\`, `//`) are refused, unknown flags refused. Auto mode keeps the current allow-list with the same argument checks. |
| E8 | **Large state (review D9)** | `read {state: true}` never answers `limit`. It returns the StateView in pages: `{type: "state", state, next?}` where `effects` and `tasks` beyond `maxStateItems` (han.ts Limits, 1,000 each) are omitted and `next` is a cursor for `read {state: true, cursor}`. Executors and hosts that need one effect use `read {state: true, effect: id}` (only that effect plus policy, roles, sessions, held, guarded, agents). |
| E9 | **Docs tell the truth (review D7)** | A script `ref/sync_docs.py` rewrites every count and status line (README status, §10 counts, test numbers, vector numbers, interop numbers, round number) from `ref/list_tests.py`, `ref/RESULTS.md` and `interop/` results; `run_all.py --quick` runs it in `--check` mode and FAILS on drift. interop/RESULTS.md gets a closure section (round 21: all 22 failures resolved, with the decision for each). |
| E10 | Wire vectors coverage (review D8) | Extend `ref/wire-vectors` with a clock-injectable, multi-server harness: `unavailable` + `retryAfterMs` (R-16, R-03a), `limit`, `read {at}`, `follow` + `limit` gap, `knownHeads`, a profile space (bootstrap, notice), key rotation, a two-server federation exchange, a move handshake, frames with integers ≥ 2^53 (decision: `invalid` on the request's id when the id itself is usable, else id 0 + close). |
| E11 | Small items (review D11) | `Retry-After` header on HTTP 503; per-client limits on challenges and uploads (`limit`); X-12 back-off defaults 1 s → 30 s; X-02 logs which clock it uses; TS own-upload `blobGet` checks `ref.size`; TS executor follows `movedTo` when it has a URL for that server (from han-peers); mark SPEC-GAPS-WIRE N-01…N-13 resolved or open honestly. |
