# Decisions for round 26

From the round-25 review (74.3, defects L1–L11). Theme: **each module owns its whole job.** Policy alone knows P-15, so the Log calls one function and holds none of it. The executor claims and lets Policy judge. Every sentence about a check is true or derived. All agents follow these. Where one is silent, the owning agent decides and writes it down.

| # | Topic | Decision |
|---|---|---|
| M1 | **A held agent's own proposals wait for its guard (L1)** | An `effect.propose` authored by X while X is held raises `lastOutside[X]` to its seq, like an outside instruction. A release whose `seen` is older than that proposal is `denied`, so a release, with or without `unguard`, covers only proposals the guard had seen. Nothing new is stored. Add the reviewer's s1 repro and its forced-space variant (owners switch `forceGuarded` off, then a plain stale release) as vectors, plus a mutation. The guard model gets a "propose while held" move. Its claim property becomes the literal invariant: no effect proposed by X while X was held is claimed unless X's guard approved it or released X with `seen` ≥ that proposal's seq. That property must not restate E3. |
| M2 | **A held agent instructs no one (L2)** | While held, an agent's `effect.propose` must name itself as executor, or else it is `denied` ("a held agent can't instruct another agent"). This matches the held list in P-15, the README and HeldInstructNoOne. Vector (the reviewer's s4) plus a mutation. The guard model gets the move. |
| M3 | **The Log holds no P-15 logic (L8)** | `relevantActors(state, entry, ctx)` takes `ctx` (`time`, `profiles` so far) and returns the complete pin list. That is the author, targets, instruction targets, the release's agent, the proposer and executor, and for a claim the guards from the profiles in `ctx`. It also returns the E3 candidates in order up to and including the first whose pinned profile shows a valid key, plus every candidate not yet in `ctx.profiles` before that one. The sequencer loops: fetch what is missing, call again, until the list stops growing (at most three rounds; state the bound). An actor it can't fetch → `unavailable`. `wire.py pin()` keeps only that loop: no `guards_of`, no candidate walk, no key checks. P-01 is rewritten around it, and the function count stays six. |
| M4 | **Executors claim and Policy judges (L3)** | X-09 and §6.4 drop "apply E3 to `state {effect}`". An executor claims every `open` effect it is the executor of, at most once per head. A `denied` claim is cheap, and the executor waits for the head to move before trying again. impl `executor.py` and TS `exec.ts` drop their E3 pre-checks (`approvalsInHand` and the "cheap first half"). Nothing new goes into the effect view. |
| M5 | **Hosts call one thing (C2)** | `guardStatus` takes the `state {agent}` reply as is. Its `state` argument is `{policy, held, guarded}` (han.ts: `GuardInput`, a named type, which `SpaceState` satisfies), so a host builds no fake state. R-24 says so. |
| M6 | **Precise words (L4, L7, L11)** | The P-16 `task`/`effect.propose` rows say "guarded or forced". That is an accepted trust assumption: owners decide whom to admit (trust is per space), and `forceGuarded` doesn't protect against a profile server that lies. |

The spec agent decides whether this needs any state (it should not: the release's `seen` is at most `lastOutside` at release, so "pending work newer than `lastOutside` at the time of becoming guarded" may be enough).
